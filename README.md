# Everpine · лендинг

Next.js 16 (App Router), статический экспорт. Одна страница, без бэкенда.

```bash
npm install
npm run dev     # дев-сервер, http://localhost:4200
npm run build   # статика в out/
npm start       # посмотреть собранную статику, тот же порт 4200
```

Порты: дев-сервер и просмотр сборки — `4200`, контейнер слушает `80` внутри и мапится наружу
(`docker run -p 8080:80`). `npm start` поднимает не Next, а статический сервер поверх `out/`:
у экспорта нет рантайма, и `next start` с ним не работает.

## Для дизайнера: что где править

**Визуал целиком настраивается из одного файла — `app/tokens.css`.** В компонентах нет ни одного
литерального цвета, радиуса, шрифта или отступа секции: всё берётся из переменных. Поменяли
`--mint` — поменялся акцент на всей странице, включая линию выноски и подсветку Loop.

| Что нужно | Где |
|---|---|
| Цвета, шрифты, радиусы, вертикальный ритм | `app/tokens.css` |
| Общие стили: кнопки, заголовки, `.wrap`, `.section` | `app/globals.css` |
| Схема Loop и её анимация | `components/Loop.jsx` + `Loop.module.css` |
| Рамка скриншотов, выноска, линия к детали | `components/Shot.jsx` + `Shot.module.css` |
| Порядок секций и все тексты страницы | `app/page.jsx` |
| Полоса фактов | `components/Proof.jsx` |
| Шапка, CTA, подвал | `components/Nav.jsx`, `Cta.jsx`, `Footer.jsx` |

Каждая секция — отдельный компонент со своим CSS-модулем рядом. Классы модулей локальны:
правка `Loop.module.css` не может задеть ничего, кроме схемы.

### Анимация Loop

Тайминги вынесены в токены: `--loop-cycle` (полный цикл) и `--loop-step` (шаг узла, = цикл / 6).
Окно подсветки — `3%…15%` кадров, оно намеренно шире слота узла: при точном совпадении между
узлами остаются кадры, где не горит ничего, и лента выглядит рваной.

Кульминация на пятом узле (split-settlement) — единственное усиление в цикле. При
`prefers-reduced-motion: reduce` анимация выключается целиком, а деталь со сплитом показывается
статикой: иначе главную мысль теряет ровно тот, кто отключил движение.

Полная спецификация и обоснование решений — `../nexus-react/docs/YC_LANDING.md`.

### Кадры продукта

Скриншоты снимаются с живого прототипа (`../nexus-react/demo-video/stills-yc.mjs`), EN-перевод
инжектится на лету. Пересъёмка: поднять прототип и запустить скрипт — файлы пишутся прямо
в `public/assets` этого проекта, промежуточной папки нет.

**Кадр кропится под ту ширину, в которой показывается.** Снятые 1088 CSS-пикселей в колонке
510px делают текст вдвое мельче и таблицу нечитаемой, поэтому у блока Inventory вся ширина,
а у вертикальной split-карточки узкая колонка. На мобиле показываются отдельные узкие
фрагменты (`*-m.png`), а не уменьшенные экраны.

## Деплой

### Vercel

Статический экспорт определяется автоматически, настройка не нужна. Задайте переменную
`NEXT_PUBLIC_SITE_URL` (например `https://everpine.io`) — она попадает в `og:url` и канонические
ссылки. Это значение **сборки**: смена адреса требует пересборки.

### Любой статический хостинг

```bash
npm run build      # результат в out/
```
Содержимое `out/` кладётся как есть (S3, Netlify, GitHub Pages, nginx).

### Railway

Railway видит `Dockerfile` и собирает по нему. Настроить нужно переменные сервиса:

| Переменная | Зачем |
|---|---|
| `PORT` = `8080` | порт контейнера. **То же значение обязано стоять в target port домена** (Settings → Networking) |
| `NEXT_PUBLIC_SITE_URL` | публичный адрес; уходит в `og:url` и канонические ссылки. Railway передаёт переменные сервиса в сборку, а `ARG` в Dockerfile её принимает |
| `TG_BOT_TOKEN`, `TG_CHAT_ID` | куда уходят заявки с формы (см. ниже). Без них форма отвечает ошибкой и показывает почту |

**Порт задаётся явно с обеих сторон.** Автоопределение целевого порта у домена оказалось
ненадёжным: у сгенерированного домена target port живёт своей жизнью и может остаться от
прежней конфигурации сервиса, сколько бы `EXPOSE` ни стояло в Dockerfile. Пока значения не
совпали, каждый запрос заканчивался 502 при полностью рабочем контейнере.

**Порт задаёт платформа.** Railway передаёт его в `PORT` и проксирует именно туда. Поэтому
`nginx.conf.template` слушает `${PORT}`, а не зашитый порт: entrypoint образа подставляет
значение при старте. Зашитый `listen 80` даёт «Application failed to respond» при полностью
рабочем контейнере, и по этой ошибке невозможно догадаться, что дело в порте.

**И IPv6.** Вторая половина той же ловушки: внутренняя сеть Railway адресуется по IPv6, поэтому
в шаблоне есть отдельная строка `listen [::]:${PORT};`. Штатный скрипт образа
`10-listen-on-ipv6-by-default.sh` добавил бы её сам, но отрабатывает **до** envsubst (`10-`
против `20-`) и правит ещё дефолтный конфиг — наш шаблон затирает его результат.

Симптом у обеих ошибок одинаковый и обманчивый: в deploy logs nginx рапортует об успешном
старте, а браузер получает 502 с заголовком `X-Railway-Fallback: true`. Он означает, что
запрос до контейнера не дошёл вообще, — искать причину надо в том, где слушает сервер,
а не в приложении.

Смена адреса сайта требует **передеплоя**, а не перезапуска: адрес вшивается в статику на этапе
сборки.

## Заявки с формы → Telegram

Форма постит на свой же адрес `/api/lead`, оттуда nginx отправляет её в Telegram Bot API.
**Токен подставляется в конфиг при старте контейнера и в браузер не попадает.** Запрос из
браузера прямо в `api.telegram.org` был бы проще, но положил бы токен в бандл — а это полный
доступ к боту любому, кто открыл «Просмотр кода» на странице для инвесторов.

**Посетителю канал доставки не виден.** Он получает пустой `204` от нашего же сервера: ни
ответа Telegram, ни его заголовков наружу не уходит. Поэтому здесь `mirror`, а не прямое
проксирование — в теле ответа Telegram лежат имя бота и id чата, и в DevTools это читалось бы
с первого взгляда, а при отключённом JS обычный сабмит уводил бы посетителя прямо на ту
страницу. Обратная сторона: статус доставки клиенту неизвестен, форма подтвердит приём в любом
случае — поэтому проверка только по чату.

Грабля на будущее: ответ отдаёт петля `proxy_pass` на себя, а не `return 204` рядом с
`mirror`. `return` завершает запрос на фазе rewrite, а зеркало живёт на фазе precontent — до
неё дело не доходит, и конфиг молча не отправляет ни одной заявки, оставаясь с виду рабочим.

Настройка — три шага, все вне кода:

1. **Бот.** В Telegram написать [@BotFather](https://t.me/BotFather) → `/newbot` → он вернёт
   токен вида `1234567890:AA...`.
2. **Чат.** Написать своему боту любое сообщение (иначе он не имеет права писать первым), затем
   открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и взять оттуда `chat.id`. Для группы
   бота нужно сначала в неё добавить; id группы отрицательный.
3. **Переменные сервиса** в Railway: `TG_BOT_TOKEN` и `TG_CHAT_ID`. Railway перезапустит
   контейнер сам — пересборка не нужна, значения читаются при старте, а не при сборке.

Проверка после настройки — реальной отправкой формы. Если переменные не заданы или неверны,
Telegram отвечает `401`, посетитель видит «Something went wrong» и почту рядом: заявка не
теряется молча.

Локально: `docker run -e TG_BOT_TOKEN=... -e TG_CHAT_ID=... -p 8080:80 everpine-landing`.

Известное ограничение: тело запроса уходит в текст сообщения как есть — чистый nginx его не
санирует. Практический риск — спам в чат, ровно тот же, что у любой открытой формы. Появится
шум — ставить капчу или выносить релей в отдельный сервис.

### Docker (тот же путь, что у остального стека)

```bash
docker build -t everpine-landing --build-arg NEXT_PUBLIC_SITE_URL=https://everpine.io .
docker run -p 8080:80 everpine-landing          # без PORT слушает 80
docker run -e PORT=8090 -p 8090:8090 everpine-landing   # как на платформе
```

`nginx.conf` уже задаёт чистые URL, свою 404, бессрочный кэш для файлов с хэшем в имени,
недельный для кадров продукта и базовые security-заголовки.

## Бюджеты

Замерено на собранной статике:

| | Размер |
|---|---|
| Графика (3 кадра + 2 мобильных + OG) | 188 KB |
| Шрифты (3 семейства, самохост) | 91 KB |
| JS | 184 KB gzip (516 KB без сжатия) |
| CSS | 4 KB gzip |

Шрифты самохостятся через `next/font`: стороннего домена в критическом пути нет, а значит нет
лишних DNS и TLS до первого текста. Внешних запросов у страницы ноль.

JS — это рантайм React и Next; собственного клиентского кода на странице один компонент
(`components/Reveal.jsx`, появление секций при скролле через IntersectionObserver). Если этот
бюджет окажется тесным, единственный честный шаг — убрать островок и заменить его CSS-анимацией
по скроллу; каркас Next при этом всё равно останется.
